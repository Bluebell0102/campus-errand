## 1. 背景与问题

校园里每天都有大量“顺手就能帮”的小需求：驿站取快递、食堂带饭、超市代买、图书馆占座、送文件。目前这些需求主要靠 QQ 群、表白墙、朋友圈临时喊人解决，存在三个问题：

- **找不到人**：消息被刷屏淹没，没有按地点、时间组织需求，跑腿方也看不出哪些单顺路。
- **不敢托付**：要把取件码、手机号交给陌生人；代买要别人先垫钱；交付后“说没收到”无法举证。
- **没有约束**：放鸽子、拖欠、违规需求（代课代考、代签到）没有任何成本。

**核心判断**：这件事的瓶颈不是“信息撮合”，而是**陌生同学之间的信任**。产品要把信任拆成三件可执行的事：身份可信（校内实名）、资金可信（托管）、履约可信（交付码 + 信用）。

> 待验证假设（试点前用问卷 + 访谈验证）：① 校内有跑腿需求的学生中，过半曾因“不放心陌生人”而放弃找人帮忙；② 跑腿方愿意为 3–5 元赏金顺路带单；③ 交付码不会明显增加使用负担。

## 2. 目标与指标

| 层级 | 指标 | 试点目标（第 1 个月） |
|---|---|---|
| 北极星 | 30 分钟接单率 | ≥ 70% |
| 供需 | 周活跃跑腿者 / 周活跃发单者 | ≥ 0.4 |
| 履约 | 履约完成率（完成 / 已接单） | ≥ 95% |
| 信任 | 纠纷率（申诉 / 已接单） | ≤ 2% |
| 留存 | 发单 7 日复购率 | ≥ 35% |
| 安全 | 违规任务曝光数 | 0（发布即拦截或 2 小时内下架） |

目标值是试点前的设定值，以试点数据回校。

## 3. 用户与场景

| 角色 | 典型画像 | 核心诉求 |
|---|---|---|
| 发单方 | 课多、宿舍离驿站远的低年级学生；赶 DDL 不想出门的高年级学生 | 快速有人接、东西安全、价格合理 |
| 跑腿方 | 每天固定路线往返教学楼 / 食堂的学生；想赚零花钱的学生 | 顺路、不亏钱、不惹纠纷 |
| 运营 / 学校 | 平台运营、学生会权益部 | 纠纷可仲裁、违规可拦截、数据可看 |

**关键用户故事**

- 作为发单方，我想在 1 分钟内发完一个取快递任务，并且只让接单的人看到取件码。
- 作为跑腿方，我从宿舍去图书馆时，想看到这条路上顺手能带的单。
- 作为跑腿方，代买时我先垫了钱，希望完成后一定能拿回来。
- 作为发单方，东西放门口却没找到时，我希望有人能主持公道。
- 作为运营，我需要一个地方集中处理举报和申诉，并看到平台健康度。

## 4. 范围

**MVP 做（本原型已实现）**

| 模块 | 功能 | 优先级 |
|---|---|---|
| 账号 | 校园实名认证（学号 + 校园邮箱 + 学生证） | P0 |
| 任务 | 四类任务发布、建议赏金、违规词拦截 | P0 |
| 大厅 | 分类筛选、搜索、五种排序、顺路模式 | P0 |
| 交易 | 赏金托管、垫付返还、交付码、无接触交付、自动确认 | P0 |
| 信用 | 信用分、等级、权益门槛、双盲互评、信用明细 | P0 |
| 沟通 | 订单内消息、催单、消息通知中心 | P1 |
| 治理 | 举报、申诉、运营后台仲裁、数据看板 | P1 |
| 增长 | 加价、再来一单、本周跑腿榜 | P2 |

**MVP 不做**：真实支付与分账（先用模拟钱包验证流程）、实时定位与地图、外卖平台对接、跨校区 / 跨校、抽成。理由：先验证“信任机制能否让陌生同学愿意互相托付”，再投入支付与地图这类重成本能力。

## 5. 功能需求

### 5.1 校园实名认证

- 输入学号（8–12 位数字）、校园邮箱（收验证码）、上传学生证；通过后信用 +20。
- 未认证用户可以浏览大厅，但不能发布或接单。

### 5.2 发布任务

- 类型：代取快递 / 代买物品 / 代占座位 / 其他互助；选类型后自动带出默认地点和对应字段（快递有取件码，代买有垫付金额，占座只有一个地点并提示占座规则）。
- 建议赏金 = 类型基础价（3/4/3/5 元）+ 每 400 米 1 元 + 大件 3 元 + 30 分钟内 2 元（1 小时内 1 元）+ 垫付超 100 元 2 元。用户没改过赏金时，改地点、时间等字段会自动刷新建议值；手动改过后不再覆盖，并提供“使用建议价”。
- 标题和备注实时检测违规词，命中即提示并禁止发布。
- 发布时从余额冻结赏金；余额不足不能发布。取件地点与送达地点不能相同。

### 5.3 任务大厅

- 只展示待接单任务；卡片显示类型、标签（大件 / 垫付 / 顺路）、路线、距离、截止时间、发布者信用。
- 排序：智能（顺路分优先，其次截止时间）、最新、赏金最高、离我最近、即将截止。
- 顺路模式：选择“我正要去 X”，筛出起点距 X ≤300 米的任务，终点靠近我宿舍或 X 的加分并标“顺路”。

### 5.4 接单与履约

- 接单前校验：已认证、信用 ≥60、大额垫付单（>50 元）信用 ≥100、同时进行中 ≤3 单、不能接自己的单。
- 接单后解锁取件码和联系方式（虚拟号）。跑腿方可更新“已取件”，可放弃（信用 -3，任务回大厅）。
- 当面交付：发布方详情页显示 4 位交付码，跑腿方输入正确即完成。
- 无接触交付：填写放置位置并拍照，状态变为待确认；发布方确认收货或发起申诉，24 小时无操作自动确认。
- 完成时结算：跑腿方收到赏金 + 垫付款，发布方支付垫付款。

### 5.5 评价与信用

- 双方互评 1–5 星 + 标签 + 文字。双盲：双方都提交后或完成 72 小时后才公开，避免报复性评价。
- 信用变化见第 6 节；个人中心展示信用分、等级、权益、明细。

### 5.6 举报、申诉与运营后台

- 任何人可举报待接单任务；发布方可对待确认订单发起申诉，申诉期间暂停自动确认与结算。
- 运营后台：数据看板（任务数、接单率、平均接单用时、履约率、纠纷率、平均信用）、待处理队列、用户信用表、违规词库。
- 举报处理：核实则下架任务、退回赏金、发布者信用 -20；或驳回。申诉处理：支持发布者则退款、跑腿者 -20；支持跑腿者则放款、发布者 -5。

### 5.7 通知

- 接单、取件、催单、放弃、完成、过期、超时、处理结果都会通知相关方；右上角铃铛显示未读数。

## 6. 业务规则

| 规则 | 取值 |
|---|---|
| 信用分范围 / 初始值 | 0–200 / 100 |
| 等级 | 受限 <60 · 新手 60 · 可靠 100 · 优秀 140 · 金牌 180 |
| 加分 | 实名 +20；按时完成 +2；发布者完成交易 +1；获 4–5 星 +1 |
| 扣分 | 超时完成 -2；放弃 -3；获 1–2 星 -3；无理申诉 -5；违约或违规 -20 |
| 接单门槛 | 信用 ≥60；垫付 >50 元需 ≥100；同时进行 ≤3 单 |
| 垫付上限 | 500 元 |
| 无人接单 | 到截止时间自动过期，赏金全额退回 |
| 自动确认 | 无接触交付后 24 小时 |
| 催单频率 | 同一订单 5 分钟 1 次 |
| 评价公开 | 双方都评价，或完成后 72 小时 |

## 7. 订单状态机

| 当前状态 | 触发 | 下一状态 |
|---|---|---|
| 待接单 | 跑腿方接单 | 进行中 |
| 待接单 | 发布方取消 / 到期无人接 | 已取消 / 已过期（退款） |
| 待接单 | 举报核实 | 已下架（退款） |
| 进行中 | 输入正确交付码 | 已完成（结算） |
| 进行中 | 无接触交付 | 待确认 |
| 进行中 | 跑腿方放弃 | 待接单 |
| 待确认 | 发布方确认 / 24 小时自动 | 已完成（结算） |
| 待确认 | 发起申诉 | 待确认（申诉中，冻结） |
| 申诉中 | 运营支持发布者 / 跑腿者 | 已取消（退款）/ 已完成（结算） |

## 8. 非功能需求

- **隐私**：取件码、手机号仅接单双方可见，手机号走虚拟号；实名信息不对外展示。
- **合规**：违规词库可由运营维护；占座任务限 1 个座位、30 分钟内到场。
- **资金**：正式版接入持牌支付机构的担保交易，平台不直接持有资金。
- **多端适配**：手机版用底部标签栏、单栏卡片；电脑版用顶部导航、任务双列 + 侧栏；默认按窗口宽度自动切换，用户可在设置中固定。
- **性能**：大厅首屏 1 秒内可交互；弱网下操作可重试，不重复扣款。
- **可追溯**：每个订单保留进度记录与站内消息，作为申诉依据。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 冷启动供给不足 | 先在 2–3 栋宿舍楼试点；招募固定路线的“楼栋跑腿员”；首周跑腿补贴 |
| 大额垫付跑单 / 诈骗 | 大额单信用门槛；垫付上限；举报快速下架；要求平台内沟通 |
| 学校政策风险 | 主动与学生处、驿站沟通；不承接违规任务；占座遵守场馆规定 |
| 刷信用 | 同一对用户互相交易的信用增益设上限；异常频次进入人工复核 |
| 交付码体验负担 | 提供无接触交付 + 自动确认作为备选；试点中观察使用比例 |

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| M0 原型 | 本可交互原型 + 用户访谈 10 人 | 假设①②得到初步支持 |
